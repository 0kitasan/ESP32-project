## AI的建议

### 建议：不要在水下尝试连接

**重要提示：** **2.5m 甚至 40cm 的深度，Wi-Fi 信号是**完全无法**穿透的。**

- **策略：** **ESP32 在水下悬停时，**不要**尝试发送 Wi-Fi 信号，因为这会消耗大量电力且可能导致程序在等待网络反馈时卡死（Blocking）。**
- **实现方法：**
  - **在水下时，将深度数据实时存入 ESP32 的内存（数组）或 Flash 中。**
  - **通过深度传感器判断已经浮出水面（深度接近 0）。**
  - **出水后**再初始化 Wi-Fi，连接笔记本并“一键重发”所有历史数据。

---

### 更稳的选择：ESP-NOW 协议

在 MATE ROV 这种实时性要求高的比赛中，ESP-NOW **远比普通 Wi-Fi 方案（热点模式）强大：**

- **原理：** **无需连接、无需获取 IP 地址。它就像对讲机，只要频道一致，数据包发出去，对方就能收到。**
- **优势：**
  - **瞬间传输：** **浮标头部一出水，数据包就能发出来，不需要等待 5-10 秒的 Wi-Fi 握手时间。**
  - **极简逻辑：** **避免了复杂的 Wi-Fi 掉线重连逻辑。**

- **具体做法：**
  - **岸上：找另一个 ESP32 开发板，通过 USB 线连到笔记本。它专门负责接收数据并通过串口（Serial）传给笔记本。**
  - **水下：ESP32 浮出水面后，直接广播数据包。**

---

### 硬件层面的“避坑”指南

- **天线位置：** **你的 ESP32 天线必须位于浮标的最顶端。如果天线在水面以下，哪怕只有 1 厘米，数据也发不出去。**
- **IPEX 接口外接天线：** **强力建议不要使用板载的 PCB 蛇形天线。买那种带有** **IPEX 接口的 ESP32**，接一根延长线到浮标顶部的透明防水壳内，信号会好非常多。
- **UDP 优于 TCP：** **如果坚持用 Wi-Fi 热点方案，请使用** **UDP** **协议发送数据。TCP 在信号不稳时产生的握手延迟（Retransmission）可能会让你的上位机程序直接卡住。**

### 总结建议方案

- **如果你追求简单快速开发：**
  笔记本开热点 + ESP32 连接 + 固定 IP + UDP 协议。
- **如果你追求比赛时的极致稳定和速度：**
  岸上 ESP32 接收器 + 水下 ESP32 + ESP-NOW 协议。

**在写代码时，记得给 ESP32 加一个“离线存储”逻辑。如果在 30s 内没连上热点，数据要依然保存在本地，防止因为现场 Wi-Fi 干扰严重导致数据彻底丢失。**
